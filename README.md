# n8n Workflows: Slack ↔ Freshdesk Enquiry + KB Drafting

This repo includes one n8n export containing two workflows:
1. **Slack Enquiries → Freshdesk Tickets**
2. **Freshdesk Resolved → Knowledge Base Draft**

## 1) Import into n8n
1. Open n8n → **Workflows** → **Import from file**.
2. Select `n8n_export.json`.
3. Confirm both workflows are imported.
4. Open each workflow and map your Slack credentials in Slack Trigger/Slack nodes.

---

## 2) Required Environment Variables
Set these in your n8n environment (Docker `.env`, stack env, or process env):

```bash
SLACK_CHANNEL_ID=C0123456789
SLACK_IGNORE_USER_IDS=U0BOTUSER,U0ANOTHERBOT
SLACK_IGNORE_THREAD_REPLIES=true
SLACK_POST_ACK=true
SLACK_ACK_CHANNEL_ID=C0123456789

FRESHDESK_DOMAIN=yourdomain
FRESHDESK_API_KEY=your_freshdesk_api_key
FRESHDESK_GROUP_ID=
FRESHDESK_PRODUCT_ID=
FRESHDESK_TICKET_SOURCE=3
FRESHDESK_DEFAULT_PRIORITY=2
FRESHDESK_DEFAULT_STATUS=2

FRESHDESK_KB_CATEGORY_NAME=Common Issues
FRESHDESK_KB_FOLDER_VISIBILITY=3
FRESHDESK_KB_LANGUAGE=en
KB_MIN_CONFIDENCE=0.75
```

### What you must change
- `SLACK_CHANNEL_ID` to your intake channel.
- `SLACK_IGNORE_USER_IDS` to include your bot user ID (prevents loops).
- `FRESHDESK_DOMAIN` and `FRESHDESK_API_KEY`.
- Optional routing defaults (`FRESHDESK_GROUP_ID`, `FRESHDESK_PRODUCT_ID`, status/source/priority).
- `SLACK_ACK_CHANNEL_ID` if you want errors/alerts elsewhere.

## 3) Slack App Setup (for “New Message Posted to Channel”)
Create or update a Slack app and install it to your workspace.

### Bot token scopes
Add at least:
- `channels:history`
- `channels:read`
- `chat:write`
- `groups:history` (if private channels are used)
- `groups:read` (if private channels are used)
- `users:read`

### Event subscription
- In Slack App → **Event Subscriptions**: enable events.
- Use n8n’s Slack Trigger URL generated by the node.
- Subscribe to bot event for channel messages (the Slack Trigger node handles this when configured for “New Message Posted to Channel”).
- Reinstall app after scope/event changes.

### n8n webhook verification
- In n8n Slack credentials/trigger setup, provide Slack Signing Secret.
- Ensure public HTTPS URL is reachable by Slack.
- Activate workflow once verification succeeds.

## 4) Freshdesk Automation Rule (for workflow 2)
Create an Automation rule in Freshdesk (Ticket Updates / Time Trigger as preferred):

**Condition:**
- Ticket status changes to **Resolved** or **Closed**.

**Action:**
- Trigger webhook:
  - Method: `POST`
  - URL: `https://<your-n8n-host>/webhook/freshdesk-resolved-kb-draft`
  - Content-Type: `application/json`
  - Body:
    ```json
    {
      "ticket_id": "{{ticket.id}}",
      "updated_at": "{{ticket.updated_at}}"
    }
    ```

This powers KB draft generation and dedupe (`ticket_id + updated_at`).

## 5) Workflow behavior details

### Workflow 1: Slack Enquiries → Freshdesk Tickets
- Triggers on new channel message in configured channel.
- Ignores bot messages, bot IDs, edited messages, ignored users, and (optionally) thread replies.
- Deduplicates using workflow static data (`event_id` or `channel:ts`) with TTL cleanup.
- Normalizes text + simple rules classifier output in strict JSON fields.
- If confidence `< 0.5`, forces intent=`other` and adds `needs_triage` tag.
- Creates Freshdesk ticket via API.
- Optional Slack thread acknowledgement if `SLACK_POST_ACK=true`.
- On ticket-create failure, posts compact alert to `SLACK_ACK_CHANNEL_ID`.

### Workflow 2: Freshdesk Resolved → Knowledge Base Draft
- Triggered by Freshdesk webhook POST `{ticket_id}`.
- Validates payload and deduplicates retries.
- Fetches ticket + conversations.
- Redacts PII from source content (email/phone/address/name patterns).
- Builds KB draft decision JSON and gates on `KB_MIN_CONFIDENCE`.
- Finds/creates Solutions category and folder.
- Searches existing articles; updates on close match else creates new article.
- Always writes `status=1` (Draft), never publishes automatically.
- Posts Slack alert when gated out or on failures.

## 6) Test Plan (minimum 3 cases)

1. **Slack intake success**
   - Post a non-bot message in `SLACK_CHANNEL_ID`.
   - Expected: one Freshdesk ticket created, optional thread ack posted.

2. **Slack dedupe + loop prevention**
   - Replay same Slack event (or re-run execution payload).
   - Expected: no duplicate ticket.
   - Post message from ignored/bot user.
   - Expected: workflow exits with no ticket.

3. **Resolved ticket KB draft generation**
   - POST webhook with a resolved ticket id:
     ```bash
     curl -X POST "https://<your-n8n-host>/webhook/freshdesk-resolved-kb-draft" \
       -H "Content-Type: application/json" \
       -d '{"ticket_id":12345,"updated_at":"2026-01-01T10:20:30Z"}'
     ```
   - Expected: draft KB article created/updated (`status=1`) and no duplicates on retry.

4. **PII redaction sanity check**
   - Use ticket text containing email and phone.
   - Expected: KB content stores `[REDACTED_EMAIL]` and `[REDACTED_PHONE]` placeholders.
